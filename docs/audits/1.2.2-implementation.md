# Verdict

**Do not ship the watcher as written.** The core primitive is sound:
- User-origin attribute CSS.
- Apply, verify and rollback in one task.
- `documentIds`-bound `insertCSS` with fixed CSS and a validated token.
- No inline writes, and committed effects kept over SPA navigation and bfcache.
- No feedback loops. Our attributes are outside the content observer's `attributeFilter`, and `release()` disconnects before it mutates.

The regressions are in `maintain()`, the unlock CSS, and the scope checks. I did not run anything; the counterexamples below are derived from the code.

---

## High

### 1. `maintain()` permanently yields the unlock to non-modal or incidental triggers, leaving the wall hidden and the page locked

The "yield" branch fires on:
- any visible `[role="dialog"]` or `[popover]:popover-open`,
- any `[inert]` anywhere,
- any `pageObstructed()` hit.

It then returns. On the next call, `documentElement.getAttribute(UNLOCK)!==token` returns early, so the unlock is never reacquired.

This is the worst state the feature can produce: no visible wall, no scrolling, and nothing for the user to act on.

Counterexamples. Each assumes a committed `hidden` with the fixture's lock.
- **Late CMP banner.** It appears as `<div role="dialog">` (non-modal, bottom bar). The page freezes at the current scroll position. Cookie Calm then dismisses the banner, and the page stays frozen.
- **User opens a site menu or share sheet** that uses `popover`, or a `role="dialog"`, and closes it. The page stays locked. The existing modal test asserts the lock returns but never closes the dialog.
- **Absolutely positioned hero image.** The user scrolls to a figure `<div style="position:relative;height:600px"><img style="position:absolute;inset:0;width:100%;height:100%">`. Any observed mutation anywhere then fires, and ad slots and carousels make this near-certain. `pageObstructed` sees an absolute element covering ≥25% of the viewport, releases the unlock, and the page locks mid-article.
- **Carousel hydrates after commit** with `inert` on the off-screen slides, which is a recommended a11y pattern. The page locks.
- **Anti-tamper re-lock when no unlock was held.** Suppose `apply` did not take the unlock and a site script later sets `body.style.overflow='hidden'`. The early return ignores it, and we keep hiding the wall over a locked page.

**Fix (simpler):**
- Gate only on true modality: `:modal`, or a visible `[aria-modal="true"]` outside the surface.
- While a modal is present, stay yielded. When it goes away, run the same probe you already use for class changes. The ownership ambiguity is identical, so there is no new risk.
- Drop `pageObstructed` and `[inert]` from `maintain`.
- Enforce one invariant: if the viewport is locked, we hold no unlock, and no modal is present, then release the whole transaction (show the wall). Never leave the page hidden and locked.

## Medium

### 2. The unlock CSS turns `body` into a scroll container, which breaks `position:sticky` and can move scrolling off the window

Take a lock of `body{overflow:hidden}` with html unstyled, which is the most common form:
- Our `html{overflow-y:auto}` stops the body's overflow from propagating to the viewport.
- The body keeps the site's `overflow-x:hidden`. Our `overflow-y:visible` is then coerced to `auto`.
- The body is now a scrollport that never scrolls. A `<header style="position:sticky;top:0">` inside it scrolls away. It stuck correctly before the wall appeared.

With `body{height:100vh;overflow:hidden}` and html visible, `apply` passes because `viewportLocked()` sees html as `auto`. However:
- the wheel scrolls the body, not the viewport;
- `scrollY` stays 0;
- window-scroll lazy loading and infinite scroll stop firing.

The test fixture hides both problems: it locks html too and has no sticky element.

**Fix:** touch only the element that clips.
- **Html visible:** set `body[unlock]{overflow-y:auto!important}` and leave html alone. The body then propagates to the viewport and its used overflow becomes visible.
- **Html locked:** set html `overflow-y:auto`. If the body is also locked, set `overflow-x:clip;overflow-y:visible` on it. `clip`+`visible` is not coerced and creates no scroll container.

### 3. `clearContent` accepts any clear landmark, not the primary content

`describe` uses `.find()` over `article,main,[role=main]`, so the first clear match wins.

Counterexample: `<main style="filter:blur(4px)">…</main><aside><article>Related</article></aside>`. The aside article is clear, so it becomes `content`. The post-check re-tests only that article, and the result is reported as `hidden` while the story is still blurred.

**Fix:**
- Require every `main`/`[role=main]` to be clear, or pick the landmark whose rect contains the viewport centre.
- Re-check the full set in `apply`.

### 4. Hit testing misses pseudo-element backdrops

`body.adblock::after{content:"";position:fixed;inset:0;background:#000c}` makes `elementFromPoint` return `body` at every sample point. The walk sees static `body` and `html`, so the page is not flagged as obstructed. The result is `hidden` even though the page is visually covered and clicks land on `body`.

A `pointer-events:none` dimmer sibling passes the same way.

**Fix:** for sample points inside `content`'s rect, require `content.contains(elementFromPoint(...))`, allowing small sticky elements. This also removes the 25%/absolute heuristic from the apply path.

### 5. Post-commit changes of purpose or reassertion are tracked by `textContent` only

Neither of these changes `textContent`:
- A site toggles `hidden` or a class inside the surface to reveal pre-rendered text such as "You must disable your ad blocker to continue". This slips through unless `REQUIRED_AUTH`/`REGISTRATION_INTENT` happen to match it at recovery.
- A site re-shows the surface with `style="display:block!important"`, a class toggle, or on a new SPA route.

In both cases we keep hiding the wall indefinitely. The plan's `reverted_by_site` path for inline and class reassertion is missing. Only the clone case is handled.

**Fix:** have `Presentation.observer` watch the surface subtree for `attributes`, `childList` and `characterData`. Release on anything except our own attribute. This is fail-safe: the wall comes back.

### 6. Shadow DOM bypasses the scope gates

All of these use light-DOM traversal only:
- `describe`'s `querySelector('form,input,iframe,…')`,
- `ownsSurface`,
- `adblockAuthRequest`,
- `maintain`'s form check.

Counterexample: `<div id=surface>…Continue without support…<x-login></x-login></div>`, where `x-login` has a shadow root containing a password input. This passes every gate, and a later shadow-side change of purpose is invisible to us.

**Fix:** refuse if the surface contains any element with `shadowRoot` or a custom-element tag. You already track closed roots through `discoverRoots`.

## Low

- **Reversion is not reported.** A release after commit (clone, marker removed, text changed, detach before a native close) leaves the diagnostics as `hidden` and the badge as ✓. Send a `reverted_by_site` outcome. Background also needs to accept it.
- **Pause then resume leaves the wall with no retry.** `recovered()` adds the key to `done`, and `restore()` only clears budgets for the legacy `hidden` map. The legacy cosmetic path does retry. Pick one semantics deliberately.
- **Per-batch cost.** `maintain` runs `pageObstructed` (9× `elementFromPoint` plus rect/style reads, which force layout) and two `querySelectorAll`s on every observed mutation batch for the rest of the document's life. On live blogs and ad rotators this is a sync-layout-per-frame cost. Fix 1 removes most of it. Also consider a dedicated observer scoped to the surface subtree, html/body attributes, `head` childList and top-level additions, rather than piggybacking on the scanner's observer.
- **Dead exception.** `recovery` requires `surface.textContent.trim()===container.textContent.trim()`. That makes `ownsSurface`'s "Powered by …" allowance unreachable. This is safe, since it only refuses, but the code does not match its comment.

## Test gaps that would have caught these

Each of these is a single Playwright case on the existing fixture:
- Open and close a `role="dialog"` or `popover` after commit, then assert `overflowY` is back to `auto` and the page scrolls.
- Scroll to an absolute hero, then trigger an unrelated class mutation, and assert the page still scrolls.
- Body-only `overflow:hidden` lock with a sticky header: assert the header sticks.
- `main` blurred with a clear `aside article`: expect refusal.
- `body::after` fixed backdrop: expect refusal.
- `hidden` toggled on a pre-rendered paragraph inside the surface after commit: expect release.
- Surface re-shown via inline `display:block!important`: expect release and report.
- bfcache Back navigation. The plan asked for it; it is not present.
