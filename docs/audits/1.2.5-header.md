## Verdict

No blocker in the traversal logic itself. The `continue`-on-`header` is bounded (still ≤10 ancestors, boundaries unchanged), the header can't be selected, and `classify` independently refuses any container matching `header` — so the invariant is enforced twice. Two actionable items below.

## Actionable

**1. The survey exclusion list drops `aside` and `footer`, not just `header`** — `src/promotions.js`, the `surveyText` call passes `'a,button,[role="button"],nav,[role="navigation"],[role="menu"],script,style'` against a default of `'…,aside,header,footer,script,style'`. Three landmarks were removed, but only the header change is motivated by the fixture. Consequence: prose in a sidebar or page-footer landmark inside a candidate now counts as invitation evidence, and `EXPLICIT` alone satisfies `isSurveyPrompt` with no rating-group corroboration. `classify` only rejects containers *inside* `nav/aside` — it does not filter asides *within* the container. Fix is one string: keep `aside,footer` excluded, drop only `header`. The Epoch/generic fixtures use `<div class="survey-footer">`, not `<footer>`, so this is test-neutral.

**2. Missing negative fixture for the path the patch actually opens.** The `ordinary fixed page headers` test places `<header>` directly under `<body>`, so traversal stops at the `body` boundary one step later — it does not exercise the new behavior. The case that the old `break` prevented and the new `continue` permits is a Close control in a header nested inside a fixed/sticky wrapper:

```html
<div id="shell" style="position:fixed;inset:0">
  <header><b>Help us improve our site</b><button aria-label="Close"></button></header>
  <main>…</main>
</div>
```

Here `#shell` (site chrome / SPA root) becomes a structural candidate solely because of the header's Close. Today it's usually saved by the 10 000-char raw-text cap and category-pattern miss, which is incidental rather than by construction. Add this as an assert-no-click fixture, plus a short-text variant where the header carries the invitation prose, so the guard is pinned.

## Residual limits (accept, don't fix now)

- Header prose is now evidence, and `EXPLICIT` needs no rating group — so a fixed wrapper above a header whose plain-text tagline contains e.g. "take our survey" is classifiable on header copy alone. Bounded by the narrow set of non-boundary fixed ancestors, but it is the widest new path.
- `visibleOnly` uses `checkVisibility`/`getClientRects`, so clip-path sr-only header text still counts as visible evidence. Pre-existing, unchanged by this patch.
- `<header role="dialog">` is now skipped and can never be a candidate — a false negative in the safe direction.
- Other categories confirmed unchanged: `evidence` still uses default exclusions, `overlay()` still breaks on `header`, `promotion-controls`/dismissal paths untouched.
