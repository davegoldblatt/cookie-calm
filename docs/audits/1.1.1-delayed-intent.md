## Remaining blocker: html/body can get marked, which protects every prompt on the page
- The targets loop at `content.js:46–47` calls `interactions.noteChange(element.closest(CANDIDATES))`. The html/body exclusion only applies to the attributes loop.
- `CANDIDATES` includes substring matches such as `[class*="modal" i]`, `popup` and `subscription`. On a page where `<body class="modal-open">` or `<html class="…popup…">` is present, any change outside a nearer candidate resolves to body or html.
- If that change happens within 10 s of any click, body or html goes into `intentNodes`. From then on, `openedByUser` returns true for every registration prompt in the document.
- Before this change, that loop only fed `changedScopes`. So this is new, and it silently switches the feature off for the page. It errs on the safe side (nothing gets dismissed), but it's still a regression.

**Fix:** in `noteChange`, add `if (node.matches?.('html,body')) return;` before the add. That covers all three call sites. Also add a regression case: `<body class="modal-open">`, click an unrelated button that changes some text, then at more than 10 s mount the gate complete with its link, and assert that it **is** dismissed.

## Non-blocking (conservative, no action needed)
- Any subtree inserted within 10 s of a click is marked for good, for example a route change in a single-page app. A registration gate that appears later inside it won't be auto-dismissed. The old 10-second window already protected gates that appeared quickly, so the added exposure is small, and the failure only ever leaves a prompt in place.
- Reveals done purely in CSS, or through a body-class change, aren't marked. That's an accepted trade-off.
- Suggestion: add a positive control to `registration-intent.spec.js`. Run the same timeline without the Save click and expect a dismissal, so the test can't pass just because detection failed.
