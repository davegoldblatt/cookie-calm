## Remaining concrete gaps (ranked)

**1. `existing` is snapshotted with the weak predicate, so pre-existing fixed *wrappers* get exempted — a real false-absence path.** `startCompletion` filters candidates with `equivalent` = `teaserSurface`, which any fixed/sticky container holding a `TEASER_CLOSE`-matching button satisfies — including a portal root or backdrop wrapper that merely *contains* a close button. If the site re-mounts the replacement teaser inside that wrapper and the replacement is not itself `fixed`/`sticky`, `inspect` finds `equivalent(node)` false, `surface(node)` false, walks to the exempt ancestor and breaks — completion granted with a teaser on screen. Targeted fix that preserves the accepted M4 behaviour: build the `existing` snapshot with the full `offerTeaser(node)` contract rather than `teaserSurface` (keep `teaserSurface` as the *equivalence* predicate). A portal wrapper fails `offerTeaser` (extra controls/text), so it stops being exempt; an identical sibling teaser still passes and is still exempt. Don't instead restrict the break to depth 0 — that would re-break the accepted identical-sibling case on any re-render inside the sibling.

**2. Node reuse defeats the identity-based exemption.** `existing` is a `WeakSet` of nodes held for the lifetime of the action. If the site reuses that same sibling node to render the replacement, it stays exempt permanently. Consequence chain: false `absent` → `succeeded` → `verified.add(container)`, which in `available` bypasses the 4s cooldown; `count < 2` still caps it at two clicks, so this is a coverage limit, not an unbounded-action bug. Recording the snapshot-time opener label per existing node and dropping the exemption when it changes would close it; otherwise document it alongside B2/B3.

**3. Shadow roots attached after `startCompletion` are unobservable.** `observe()` covers `roots()` at construction, and `inspect` only reaches a shadow root when a *light-DOM* node mutates. `attachShadow` produces no `childList` record, so a replacement teaser rendered into a newly-attached shadow root on a pre-existing host generates no records at all → `pending` empty, `surfaces` empty → dwell elapses → false absence. `offerTeaser`'s shadow veto doesn't help here; it governs the click target, not replacement detection. Mitigation: re-scan hosts for `openOrClosedShadowRoot` once per `settled()` poll under the existing `LIMIT`, or treat "shadow root observed that wasn't at start" as `exhausted`.
