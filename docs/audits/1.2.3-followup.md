## Verdict: no new blocker

Both findings are addressed as described.

**Fail-open on closed-shadow API** — Closed. `!chrome.dom?.openOrClosedShadowRoot || chrome.dom.openOrClosedShadowRoot(container)` refuses when the API is missing *and* when the exact candidate itself hosts a root, so absence now fails closed instead of silently skipping the check. The top-position guard also means the existing descendant scan can rely on the API being present. Restricting descendant probing to `HTMLElement` is sound: per spec `attachShadow` is unavailable on SVG/other non-HTML elements, so there is no reachable host you're skipping.

**Unconstrained reviewed-button subtree text** — Closed for DOM text. `textContent` (not `innerText`) is the correct choice here since it captures `display:none`/`hidden` subtrees, so both new negative fixtures (`<p>` and `<span hidden>`) are rejected by the `['','Close']` allowlist. Allowing `''` for the SVG-stripped fixture and `'Close'` for the provider's real `<svg><title>Close</title>` is consistent — `textContent` does include SVG `<title>`. Combined with exact `type`/`aria-label`, `label(close) === 'dismiss privacy notice'`, and the exact-normalized body, the injectable surface inside the control is now bounded.

## Limitations

- **Residual non-`textContent` text.** `textContent` does not see CSS `::before`/`::after` `content`, `img` `alt`, or externally-referenced `<use>` content. A sighted user could still be shown consent-altering text inside the button that your predicate cannot observe. The accessible name is pinned by `aria-label`, so AT users are covered; this is a visual-only residual. Fully closing it needs `getComputedStyle(el, '::before')` over descendants — reasonable to defer, worth recording rather than fixing now.
- **`chrome` global vs. `chrome.dom`.** `chrome.dom?.` guards a missing `dom` namespace but not a missing `chrome` binding — that throws `ReferenceError` rather than returning `false`. Always defined in an MV3 content script, so this is only a concern for non-content-script reuse or a jsdom harness that doesn't stub the global. `typeof chrome === 'undefined' || !chrome.dom?.openOrClosedShadowRoot` would make the fail-closed property total.
- **Test coverage gap on the fix you just made.** The negative variants exercise the subtree-text path, but nothing described covers the shadow-root path: no case with `chrome.dom` undefined asserting `false`, and none where the candidate `aside` itself has a closed root. That's the branch most likely to silently regress, since positive tests run against the real extension where the API always exists. I'd add those two.
- **Case sensitivity.** `'Close'` appears case-sensitive while `label(close)` is lowercased. Divergence is fail-closed (a provider shipping `close`/`CLOSE` yields a false negative, not a bypass), so it's a robustness note, not a safety one.
