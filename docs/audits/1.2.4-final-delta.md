## One remaining blocker: per‑poll ancestor memoization truncates chains order‑dependently

`inspect()` walks at most 10 levels (`depth<10` → node + 9 ancestors) and now breaks on `this.checked.has(current)` *before* learning anything from that ancestor. The memo records only "visited", not "visited with how much budget left", so a node visited near the end of one walk poisons a later walk that still had budget to reach a surface.

Counterexample. `S` is a pre‑existing `position:fixed` overlay (not in `pending` — it never mutates itself; a site script toggles classes on descendants to reveal it). `Z` is 9 levels below `S`; `X` is `Z`'s child, 10 levels below `S`. Both get a `class` attribute mutation in the same poll, and the records arrive `X` then `Z` (mutation order is the page's, and attribute records are added with `deep=false`, so the document‑order guarantee of the `TreeWalker` path does not apply here):

1. `inspect(X)` walks `X` + 9 ancestors — reaches the node 1 below `S`, never `S`. It marks `X` and all 9 ancestors, **including `Z`**, in `checked`.
2. `inspect(Z)` → first iteration `current===Z`, `this.checked.has(Z)` → `break`. Zero ancestors examined.
3. `S` is never added to `this.surfaces`.

With the container gone and no other pending work, `remaining` is `false`, `exhausted` is `false`, `pending.size` is 0 → `settled(true)` returns true after `ABSENCE_DWELL` and the run reports `closed`/counts a dismissal while `S` still covers the viewport. Reverse the record order and the same DOM yields the correct withholding — the verdict depends on the page's mutation ordering, which is exactly the false‑success mode the rest of this design avoids.

The existing tests don't catch this: `audit-ancestor` uses a 1‑level `aside`→`section` chain, and the churn test coalesces into a single deep `main` walk where the `TreeWalker` visits parents first, so every chain is discovered top‑down.

### Fix

Make the memo budget‑aware rather than boolean, or make it carry the result:

- `checked` as `Map<Element, remainingDepth>`; break only when the cached entry was reached with remaining depth **≥** the current walk's remaining depth, otherwise continue (and update). This keeps the dedup win for the common top‑down case and costs nothing when budgets are equal.
- Or cache the *resolution* (`Element|null` surface) per node and, on a hit, adopt it instead of breaking — but this is only sound if the cached resolution was computed with at least as much depth, so it reduces to the same condition.

Either way the `inspected`/`LIMIT` cap still bounds total work, and re‑walks are charged against it, so the exhaustion path stays conservative.
