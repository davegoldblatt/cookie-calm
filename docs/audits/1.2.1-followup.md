# Static audit: Cookie Calm adblock dismissal, follow-up

## Blocker introduced by this change

### B1. The sign-in veto does not read the full text

**Where:** `src/promotions.js:50`, with `promptText` at `src/promotions.js:30-38`.

The adblock exemption is meant to bypass the full-text `REGISTRATION_INTENT` refusal at line 54 only when the prompt has no sign-in wording outside the incidental Sign in control. The veto at line 50 does not check the full text. It checks `promptText(container)`, which:

1. Drops all text under `header`, `footer`, `aside`, `nav`, `[role="navigation"]`, `[role="menu"]` and under any `a`. That includes `a[href]` links, which are not dismissal controls at all.
2. Stops after 300 text nodes. Whitespace-only nodes count toward the cap.

The only full-text check is `REQUIRED_AUTH` on `textContent`. It does not match plain wording such as "Sign in to continue."

**Reproduction.** Each of these is dismissed through `#decline`. The existing test at `tests/adblock-prompts.spec.js:66` shows the same wording in a `<p>` is refused.

- `prompt(decline,'<footer><p>Sign in to continue.</p></footer>')`
- `prompt(decline,'<header>Log in to keep reading</header>')`, or the same text in `<aside>`
- `prompt(decline,'<p><a href="/login">Sign in to continue reading</a></p>')`
- `prompt(decline,'<i> </i>'.repeat(300)+'<p>Sign in to continue.</p>')`

For all four, the trace is the same:
- The heading gives visible authorization early.
- The veto text never contains the sign-in phrase.
- `isRegistrationPrompt` is false because `INVITATION` needs "continue/keep reading" or "free account".
- Line 54 is skipped, and `adblockChoice` returns `#decline`.

**Fix.** Keep the authorization walk as it is. Build the veto from the whole container:
- Walk every text node, with no landmark exclusion and no node cap. The `<3000`-character gate already bounds the cost.
- Exclude only text inside controls whose `label()` is exactly a short sign-in label, such as `/^(sign[ -]?in|log[ -]?in|register)$/`.
- Keep the text of longer links, like "Sign in to continue reading", in the veto.

Add the four fixtures above as negative cases.

## Introduced, but not blocking

- **Performance (`promotions.js:47`).** `promptText(container,true)` runs a style and layout check on up to 300 text nodes for every non-rule candidate on every scan. That covers up to 100 `CANDIDATES` plus 40 structural containers per root. It runs again in `finished()` about 22 times per action, because `observe` fires every 100 ms for 2.2 s. The `[class*="promo"]` selector alone matches many article teasers on news pages.
  - Fix: gate it with `ADBLOCK_REQUEST.test(text)` first, e.g. `const requestText=!rule && ADBLOCK_REQUEST.test(text) ? promptText(container,true) : ''`.
- **Test witness for the 2-attempt cap (`tests/adblock-prompts.spec.js:92-98`).** Without the cap, a third click would happen when the second scan's 4300 ms fallback fires, at about 8.7 s. The test's observation window ends at about 9.0 s. That ~250 ms margin shrinks with guard round-trip latency, so a cap regression could slip through intermittently.
  - Fix: wait past the 15 s configure fallback, or assert the stored attempt state directly.
- **Paused-site negative (`tests/adblock-prompts.spec.js:86-89`).** It has no witness that the scanner was loaded and chose not to act. It is weaker than the other negatives, though absence is inherently hard to prove here. One option is to assert that the stored tab status or badge is empty or paused.

## Inherited or documented limits (not blockers)

- **`visible()` is not "strong visible" evidence.** Screen-reader-only text (clip or 1px offscreen), `font-size:0` and `color:transparent` all pass it. An accidental match on a non-adblock dialog is implausible, and the payoff is limited to bypassing the sign-in exemption.
- **Nested-control ownership only recognizes semantic boundaries.** A div-based nested panel with the only visible Close is still selected. For example, `prompt('', '<div><h2>Reading settings</h2><button type="button">Close</button></div>')` clicks the wrong Close. This matches the stated scope, "unrelated nested semantic panels excluded". The generic path at line 164 has always picked the first Close.
- **User intent is not recorded for some reveals.**
  - `noteChange` skips reveals done only on `html`/`body` (class or style changes), and reveals done with CSSOM or stylesheet changes.
  - If the user clicks Play and a 10 s window then passes with no scan, the pre-rendered wall is treated as not user-opened. That happens during a long consent `runNext` flow (up to 18 s) or while the tab is hidden.
  - Inserted walls are handled correctly. Treat this as a documented limit of the 10 s design.
- **Arriving through an in-site SPA route click marks the wall as user-opened.** The wall is then permanently protected. This is conservative, so it is recall loss only.
- **Adding `a:not([href])` spends the structural scan cap of 160 on unrelated JS anchors.** A wall appended late in a large DOM can be missed on full scans. Scans scoped to inserted nodes still find it.
- **The authorization walk skips text in `header` and `aside`.** Modal titles in `<header>` never authorize. This is a false negative only.
- **The download guard now includes buttons and href-less anchors.** Any visible "Download" or "Install" control pauses acceptance, which is the safer direction.

## Items checked and found correct

- The native Vox/Admiral handler order is `['native-close','decline']`.
- The hidden Close is excluded by `clickable`.
- Uniqueness and ownership are rechecked synchronously between `observe()` and `target.click()`.
- `form=external` submit buttons, `label` wrappers, `javascript:` and `href` links, and `aria-disabled` are refused.
- SVG `<a xlink:href>` matches `a:not([href])` but has no `.click()`, so it throws and ends as blocked rather than navigating.
- Diagnostics use the `adblock` category.
- The negative witness order is sound: the sentinel is removed after `promotions.find` in the same scan.

## Verdict

**Not ready to merge.** One introduced blocker remains: B1, where sign-in wording in landmarks, links, or past node 300 escapes the veto. The fix is small and local to line 50, plus four negative fixtures.

M2 and M5 are addressed apart from the minor test-margin notes. M1, M3 and M4 are addressed within their documented limits.

The final suite on the current code has not run yet, so merge readiness cannot be confirmed until it passes with the B1 cases added.
