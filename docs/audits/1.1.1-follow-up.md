## Remaining blocker: the 10-second window starts when the scanner gets to the prompt, not when the prompt appears

`interactions.js:49` compares the current time with the last click at the moment `permits()` runs. It doesn't compare it with when the prompt appeared. The previous review asked for a first-seen time, and that isn't recorded anywhere. The scanner can get to a prompt well over 10 s after the click:

- **A consent flow is running.** Each scan runs promotions first, then `engine.runNext()` (`content.js:205`). That call has an 18 s deadline (`rule-engine.js:129`), and `waitcss` can keep polling until then. While a scan is running, new page changes only set `dirty` (`content.js:124`). So if the user clicks Save and the prompt mounts 2 s later, the next scan can run about 16 s after the click. At that point the prompt isn't protected and gets dismissed.
- **The tab is hidden.** `schedule()` returns early while the tab is hidden and doesn't remember that a scan is owed (`content.js:123`). A prompt that mounted before the user switched away is first checked on return, which can be past 10 s.

Your tests don't catch this because they run on idle pages, where the scan follows the mount within about 500 ms.

**Minimal fix.** Record the time when the page changes, because the change observer runs even while a scan is busy or the tab is hidden:
- `interactions.js`:
  - In `reset()`, add `this.intentNodes = new WeakSet();`.
  - Add `noteChange(node) { if (Date.now() - this.gestureAt < 10000) this.intentNodes.add(node); }`.
  - Add `openedByUser(container) { for (let n = container; n; n = n.parentElement || n.getRootNode?.().host) if (this.intentNodes.has(n)) return true; return false; }`.
  - Change line 49 to `if (category === 'registration' && (Date.now() - this.gestureAt < 10000 || this.openedByUser(container)))`.
- `content.js` `processMutations`: call `interactions.noteChange(node)` for each node in `added`, and `interactions.noteChange(container)` in the targets loop at lines 42–45. That second call covers prompts revealed by an attribute change on the prompt or on something inside it.

**Regression test (deterministic, no timing race with a consent flow):**
1. Click "Save".
2. At 1.8 s, mount the gate's container without its sign-in link, so it can't be classified yet.
3. At about 11 s, add the `Sign in with email` link.
4. Assert that no dismissal happens.

The current code dismisses in this case; the fixed code must not. Optionally, add a second case that uses `/cookiebot-stuck`. Only rely on it if the test first asserts that the consent flow is actually running when the click happens.
