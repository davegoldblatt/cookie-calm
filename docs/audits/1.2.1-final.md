**Why B1 is closed**

- `adblockAuthRequest` walks every text node under the container. It no longer uses the landmark, link, or button exclusions, or the 300-node cap from `promptText`. Footer, header, aside, links, hidden text and late text all reach `REGISTRATION_INTENT` (`src/promotions.js:39-60`).
- `FILTER_SKIP` on non-exempt elements still visits their children. `FILTER_REJECT` drops only the subtree of an exempt control. Since that control's `textContent` must trim to exactly `sign in`, `log in` or `register`, nothing else can hide inside it.
- The exemption needs both the label and the text content to be the short form. If either differs (a longer `aria-label`, internal newlines, extra words), the control stays in the veto. Every mismatch errs toward refusing, never toward authorizing.
- Budget exhaustion returns `true`, which vetoes rather than approving. The `text.length>6000` check runs before appending, so the last node can overshoot slightly. That text is still tested after the loop, so nothing is lost.
- The walker only runs after the `adblockRequest && text.length<3000` short-circuit, so ordinary candidates pay no extra cost.
- `eligible()` calls `classify()` again, so the veto is re-checked at action time. No stale-authorization window is introduced.

**Behavioural change I checked**

The veto text now includes link and button text that `promptText` used to exclude, such as "Continue without support", "Allow ads" and "Not now". Only a match on `REGISTRATION_INTENT` would cause a false veto. The existing positive tests and the live Vox probe show that this does not happen for the target shape. Any new false vetoes would only mean fewer dismissals, not unsafe ones.

**Non-blocking notes**

1. **Some new fixtures may not test the fix.** The footer, aside and 300+-node fixtures all use "Sign in to continue." If `REQUIRED_AUTH` already matches that phrase through `container.textContent` (line 72), those cases passed before the fix and prove nothing about `adblockAuthRequest`. Consider adding one fixture per path, footer and late text at least, whose phrase matches `REGISTRATION_INTENT` but not `REQUIRED_AUTH`. That would show the new walker is what refuses. I can't see either regex, so I can't say whether this gap exists.
2. **Element traversal is unbudgeted.** `count` only counts text nodes, so a large tree with little text walks every element. This only affects performance, it runs only on adblock-worded visible panels, and `promptText` has the same pattern.
3. **Script and style text is included**, which is not the case in `promptText`. This can only cause extra vetoes. It's acceptable, and arguably better given the "refuse on doubt" design.

Shadow-DOM text is not walked, but that is inherited from before and not introduced here.
