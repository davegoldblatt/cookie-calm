## B1. The C2 fix reintroduces the failure it was meant to prevent, during the open transition

`src/onetrust-groups.js`, `observe()`:

```js
if(!this.interactionRoots().some(visible)){opened=false;return {stage:'absent'};}
```

`opened` is now cleared on *any* observation where neither surface is visible — including the transient frame between "banner hidden" and "preference center rendered", which is exactly the window our own open click creates.

Counterexample (real-provider shape; OneTrust builds the preference center on demand):

1. `plan()` → `open`; `onActivate` sets `opened=true`; we click `a.zdcOpenPc`.
2. The handler hides the banner immediately and the panel mounts ~200–400 ms later.
3. Poll at t≈100 ms: neither root visible → `observe()` sets `opened=false`, returns `absent`. Because `action.type==='open'` is not in `['save','reject','dismiss']`, the loop does **not** return `closed`; it keeps polling.
4. Poll at t≈300 ms: panel visible, `opened===false` → `{stage:'blocked',reason:'user-interaction'}` → `if (after.stage === 'blocked') return result('blocked', 'user-interaction')`.

End state: the panel we opened is left open with nothing changed, the diagnostic falsely attributes the abort to the user, `finishConsent` does not release (outcome is neither `closed` nor `saved`), so `claimedOwner` persists, `engine.exclusive` stays true, and the generic reject and acceptance fallbacks are suppressed for the document's lifetime. That is the C1 end state reached through timing instead of markup.

The reset is also **redundant**. `opened` can only become true inside a run (`activated` is reached only via `onActivate`), and `runPrompt`'s `finally { adapter.dispose?.(); }` runs on every exit path, clearing it. The `observe()` reset adds no protection against a later user-opened panel and only creates this false negative. Dropping it from `observe()` and relying on `dispose()` is sufficient and strictly safer.

Repro with the existing fixture hooks:

```js
await visit(page,{openNoop:true,
  afterOpen:'setTimeout(()=>{bar.hidden=true;},0);setTimeout(()=>{panel.hidden=false;},300);'});
// expect actions to reach 'save'; currently stops after 'open' with reason 'user-interaction'
```

`grouped-notice.js` hides the banner and shows the panel in the same synchronous handler, so no current test can see this.

## B2. The C7 shadow/custom-element veto skips the panel element itself

`src/onetrust-groups.js`, `preferences()`:

```js
const descendants=[...panel.querySelectorAll('*')];
if(descendants.length>1000 || descendants.some(node=>node.localName.includes('-') || node.shadowRoot ||
    node instanceof HTMLElement && chrome.dom?.openOrClosedShadowRoot?.(node)))return null;
```

`querySelectorAll('*')` excludes `panel`. `src/presentation.js` gets this right in the equivalent check — `const descendants=[surface,...surface.querySelectorAll('*')]` — so this is an inconsistency with the project's own established pattern, not a judgement call.

Counterexample: `#onetrust-pc-sdk` carries a shadow root whose template is `<slot></slot>` plus an extra default-on permission control (`<input type="checkbox" checked>` for "Sell or share my personal information"). The light DOM renders normally through the slot, so every existing check passes:

- top-line `panel.querySelector('form,…,[role="switch"],[role="checkbox"],[role="radio"]')` — does not pierce shadow;
- the descendants veto — `panel` not in the list;
- `panel.querySelectorAll('input')` / `inputs.length>20` / the `templateFields` allowlist — do not pierce shadow;
- `visible(save)` / `usable(save)` — the slotted Save renders.

Result: we click Confirm My Choices with an unseen permission at its default. The fully-shadowed variant (no `<slot>`) is already contained because the light-DOM Save fails `clickable()`, but the slotted variant is not. The same hole covers a panel whose own local name is hyphenated (`<x-pc id="onetrust-pc-sdk">`).

One-character-class fix: `const descendants=[panel,...panel.querySelectorAll('*')]`. The three `audit-regressions` preflight cases all attach the shadow root to a *child* of `panel`, so they pass while the panel-level case does not.

## B3. `PromptCompletion` exhaustion is still sticky on the benign-churn path, and the new test is calibrated just under the cap

`settled()` resets `this.inspected=0` per poll, which addresses the `inspect()` half of C5. The `add()` half was not changed:

```js
if(!this.pending.has(node) && this.pending.size>=256){this.exhausted=true;return;}
```

`exhausted` remains permanent for the object's lifetime, and this branch fires on *volume of change*, not on inability to look — the opposite of the rationale that justified making `inspected` per-poll.

Counterexample, and why the new test misses it: `tests/audit-regressions.spec.js` churns **170** spans. Because `record()` re-`add`s the same 170 nodes every tick, `pending.size` plateaus at 170 and never reaches 256. Change `.repeat(170)` to `.repeat(300)` and the 257th distinct node trips `exhausted` on the first tick; `settled()` then returns `false` unconditionally, so:

- `finished()` never becomes true for a prompt that *was* actually removed,
- `promotions.succeeded()` is not called and no `promotion-dismissed` is sent,
- `available()` permits a second click 4 s later (`state.count < 2`), which then fails `eligible()`.

A 300-row virtualized list render, an ad refresh, or a route transition animating a grid all clear 256 distinct nodes in one 100 ms interval. The fix that matches the `inspected` rationale is to treat a pending overflow as "defer this poll" (clear the surplus and return false for this poll) rather than as permanent exhaustion; only failure to *inspect* within budget should be sticky.

## Smaller confirmed items

- **`Presentation.apply()` restores focus outside `interactions.automatic`.** `focused.focus({preventScroll:true})` dispatches a trusted `focusin`. `Interactions.record()` gates `focusin` on `recent()`, so when a user gesture is already within 1.5 s the event bumps `revision` and — because the restored element is typically a `button` — refreshes `gestureAt` to *now*, extending `deferPromotions` and the 10 s `noteChange` intent window by our own action. Same class as C4; `presentation` has no handle on `interactions`, so the wrap has to be threaded in (or the restore performed under a suppression flag). Narrow trigger (recovery attempted, `apply()` fails, focus was inside the surface), and no unsafe action follows, but it is self-inflicted state.

- **`startCompletion()`'s `existing` snapshot is the only unbudgeted scan in the changed code.**
  ```js
  const existing=roots().flatMap(root=>[...root.querySelectorAll(choice.rule?.container || CANDIDATES)]).filter(equivalent);
  ```
  Full-document `CANDIDATES` across up to 60 roots, then `equivalent` → `fingerprint()` → `label(title)` → `innerText` on every match, i.e. a forced layout per candidate, synchronously immediately before each dismissal click. Every comparable scan in this codebase is capped (160 / 100 / 60 / 40 / 256 / 1000 / 2500). A `.slice(0, 200)` before `filter` would make it consistent; the C6 guarantee does not need completeness, only that genuinely pre-existing siblings are covered.

- **`inspect()` has no per-poll ancestor memo.** Each mutated node re-walks up to 10 ancestors calling `getComputedStyle` in `surface()`, with no shared visited set. Making `inspected` per-poll increased the per-poll ceiling to ~2 500 × 10 `getComputedStyle` calls, and this runs during exactly the churn that invalidates style, so each call can force recalc. A `Set` of ancestors already resolved this poll removes most of it.

- **No release path for a flow that ends with the panel open** (the tail of B1, but also reachable via a slow lazy Save control). `finishConsent` releases `claimedOwner` only on `closed`/`saved`, so `unsupported`/`unconfirmed` outcomes retain exclusive ownership for the document. I read this as the deliberate policy (§6, and the adjudication is explicit that exclusivity should not be relaxed) — flagging only so the B1 fix is understood as the thing that actually prevents the bad end state, since the ownership layer will not recover from it.

- **`tests/audit-regressions.spec.js` "later manually opened panel" is weaker than it reads.** With `attempted` persisting in `histories`, a re-run would return `unconfirmed/state-did-not-change` at `attempted.has('OSSTA_BG')` even if `opened` had leaked, so the checkbox and `actions` assertions pass either way. Only the `reason==='user-interaction'` poll actually discriminates, and it would also be satisfied by an unrelated deferral. Asserting the outcome/reason pair on the specific post-re-enable record, or clearing `histories` in the test, would make the C2 claim load-bearing.

## Verified as fixed since the first audit

- `plan()` now propagates `snapshot.reason`, so `blocked/user-interaction` reaches `background.js` (prior smaller item).
- `grantsAll(save)` veto is present in `observe()` and the `#accept-recommended-btn-handler` case is exercised.
- All extension-initiated clicks in `content.js` (reject, acknowledge, accept), `rule-engine.js` (`performAction`), and `prompt-engine.js` route through `interactions.automatic`; vendor `slide` actions dispatch untrusted events and are correctly ignored by `record()`.
- `grouped-notice.js` now records `native-close`, and the `actions` equality assertions would catch a click on the banner's Close handler — the prior fixture gap is closed.
- `existing` is snapshotted before activation in both `act()` and `activated()`, and `inspect()` breaks on `existing` before the `equivalent`/`surface` test, so a pre-existing sibling that animates mid-window no longer blocks completion.
- `Promotions.find()` hoists `knownContainers` out of the candidate loop.
- The shared `interactionRevision` guard covers both the consent and promotion `closed` paths, and `content.js`'s legacy reject/accept paths compare `interactions.revision` before claiming dismissal.

B2 first (only item that can produce an unauthorized consent commit), then B1 (regression that strands the two target sites), then B3. The smaller items are safe to defer past the live run.
